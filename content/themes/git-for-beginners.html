Light experience

Leave with a working mental model and a real commit on GitHub—no branching gymnastics required.

Project ideas

  1. First repo loop — Install Git, configure name/email, git init (or clone this repo), edit a markdown file, add → commit → status → log.
  2. Hello-World contribution — Fork or branch, add your name file (or fix a typo), push, open a pull request with a clear title.
  3. Time machine drill — Make three tiny commits; use git log and git checkout / git restore to inspect an older version (without rewriting history).
  4. Cheat-sheet page — Build a one-page HTML or markdown cheat sheet of the six commands you actually used today.
  5. Commit message clinic — Rewrite five vague messages (update, fix) into “why”-focused messages for the same fake diffs.

Learning goals

  • What a commit is (a snapshot + message), not “save file”
  • Working tree vs staging area vs repository
  • Reading git status before every other command
  • Pushing to GitHub and opening a simple PR

Heavy experience

Go beyond “commit and push”: branches, merges, remotes, and recovering from common mistakes—still beginner-safe (no force-push to main).

Project ideas

  1. Feature branch workflow — Create yourname/small-change, commit there, open a PR, merge via the GitHub UI, pull main locally.
  2. Learn Git Branching levels — Complete the intro + branching sequences in the browser; screenshot your finished level board.
  3. Merge conflict lab — Two people edit the same line on purpose; resolve the conflict, commit the resolution, explain what happened.
  4. Oh My Git! night — Play through early levels as a group; pause to map game moves to real terminal commands.
  5. Repo archaeology — Clone a small public repo; use git log, git blame, and git show to answer “who changed this and why?”
  6. Personal project with history — Start a tiny project from scratch with meaningful commits (not one giant dump at the end).

Learning goals

  • Branch as a movable label pointing at a commit
  • fetch / pull / push and what “remote” means
  • Resolving a simple merge conflict calmly
  • When not to rewrite history that’s already on GitHub

Facilitator tips

  • Project the output of git status and git log --oneline --graph --all on a screen whenever someone gets lost.
  • Ban “just delete the folder and re-clone” until they’ve tried reading status once.
  • Prefer GitHub’s PR merge button over local merge demos for the first meetup.
  • Pre-install Git (or use GitHub Desktop as a safety net) before the session starts.

Suggested session flow

  1. 10 minutes: “Why version control?” with a broken-file story (lost USB / overwritten essay).
  2. Light: everyone makes one commit to Hello-World (or a sandbox fork).
  3. Heavy option: one shared conflict exercise on a throwaway branch.
  4. Demo: open the PR in the browser and celebrate the green merge.
