Theme: Internal tools

Light experience

Design a polished, accessible web surface for library life: events, hours, or wayfinding. Ship something that looks intentional on a phone and a desktop.

Project ideas

  1. Events landing page — Upcoming programs with date, time, age group, and a clear CTA (“Register” / “More info”).
  2. Digital signage concept — Full-screen page meant for a lobby display: rotating events, Wi‑Fi password area, today’s hours.
  3. Hours & holiday calendar — Simple page that answers “Are you open?” without hunting through PDFs.
  4. New books / staff picks shelf — Static or CSV-driven list with covers (placeholder images OK) and short blurbs.
  5. Accessibility pass — Rebuild an existing flyer as HTML/CSS with proper headings, contrast, and keyboard-friendly links.

Learning goals

  • Semantic HTML and accessible color contrast
  • Responsive layout (mobile lobby phone vs desktop)
  • Content structure for non-technical editors (clear headings, fewer walls of text)

Heavy experience

Build a working mock of a tool staff or patrons might actually use—reservations, discovery, or catalog enhancements. Emphasize realism over production deployment.

Project ideas

  1. Room reservation mockup — Pick a room, date, and time slot; prevent double-booking in a local data store; confirmation screen.
  2. Catalog companion browser extension — On the library’s search results page, inject Goodreads/Open Library ratings, covers, or “similar books” links.
  3. Holds / reading list app — Local-only list of titles with status (want / reading / finished) and notes; optional export to CSV.
  4. Event RSVP prototype — Form + capacity limit + waitlist message (frontend + simple backend or serverless function).
  5. Wayfinding kiosk — Interactive map of floors/rooms for a branch (SVG or image hotspots).

Learning goals

  • Forms, validation, and CRUD-ish state
  • Reading existing page structure (for extensions: content scripts)
  • Using open bibliographic APIs instead of inventing book data
  • Privacy awareness (don’t scrape patron data; mock what you must)

Working with real library systems

  • Treat official catalogs as read-only; build mocks or extensions that enhance, not replace, staff tools.
  • Ask staff before scraping or automating against production sites.
  • Prefer Open Library / Google Books for enrichment metadata (covers, subjects, ISBNs).
  • Label prototypes clearly: “Demo—not connected to real holds.”

Suggested session flow

  1. Interview a librarian or classmate for 5 minutes: what’s annoying about the current site or process?
  2. Sketch the happy path on paper (3 screens max).
  3. Build the primary flow; fake the edge cases.
  4. Demo to someone who wasn’t on your team—can they complete the task without help?
