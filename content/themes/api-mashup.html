Theme: Connecting to the internet

Light experience

Call one public API and present the result on a clean, styled page or in the terminal. Focus on request → JSON → display.

Project ideas

  1. Random joke or quote page — Fetch on load or button click; nice typography and a “new one” button.
  2. Dog / cat image browser — Random animal photo plus breed info if the API provides it.
  3. Trivia round — Multiple-choice question from Open Trivia DB; keep score for 5 questions.
  4. Word of the day — Dictionary or dictionary-style API; show definition, part of speech, example sentence.
  5. Activity suggester — Bored API (or similar) + local styling: “I’m bored” → suggestion card.

Learning goals

  • HTTP GET, status codes, and JSON
  • fetch in the browser or requests in Python
  • Rendering API data into HTML safely (avoid injecting raw HTML from strangers)
  • CORS basics (and when a tiny proxy helps)

Heavy experience

Combine two unrelated APIs into one coherent product. The “mashup” should be obvious in the UI: data from A changes what you show or play from B.

Project ideas

  1. ISS soundtrack — Track the International Space Station’s position; map lat/lon to a country/region; play a track or preview associated with that place (e.g. music API + geocoding).
  2. Weather → playlist / color theme — Current weather changes page colors and suggests an activity or song mood.
  3. News + maps — Headlines from a news API plotted near related locations (when geo data exists) or filtered by user-chosen topic.
  4. Space + Earth — Astronomy Picture of the Day next to local sunrise/sunset or moon phase for the user’s city.
  5. Translate + trivia — Pull a trivia question and offer a translation of the question text into another language via a translation API.

Learning goals

  • Sequencing async calls (wait for A, then call B)
  • Geocoding and reverse geocoding
  • API keys, env vars, and rate limits
  • Designing a UI around combined meaning, not two dump dumps of JSON

Mashup design checklist

  1. What does API A tell you?
  2. What decision does that enable for API B?
  3. What does the user see in one glance?
  4. What happens when an API is down or rate-limits you?

Suggested session flow

  1. Light: one API working end-to-end before any styling.
  2. Heavy: get both APIs returning data separately, then wire them together.
  3. Cache or hardcode a sample JSON response so you can keep coding offline.
  4. Demo the mashup idea in one sentence before showing the screen.
